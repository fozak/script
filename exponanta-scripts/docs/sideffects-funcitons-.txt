Count how many Activate transitions fired this month. Key is the stable group-by. Label variations don't fragment your metrics.

One key field in schema. Entire system stabilizes around it.

i like it. So we have adapter based (cross-document) fns and sideeffects that are document scecific.

Exactly. Two distinct layers:

sideEffects — document specific
Derived from transition key + doctype. Live in CW.sideEffects. Scoped to one doctype's FSM transition. Know about the document, its fields, its state.

js
CW.sideEffects.ActivateUser    = (run_doc) => { ... }  // User only
CW.sideEffects.VerifyEmailUser = (run_doc) => { ... }  // User only

Adapter operations — cross-document
Live in Adapters.d1. Not tied to any doctype. Work on any run_doc regardless of doctype. Handle transport, persistence, auth.

js
Adapters.d1.create           // any doctype
Adapters.d1.update           // any doctype
Adapters.d1.login            // cross-document — reads User, writes JWT
Adapters.d1.authWithPassword // cross-document — compares virtual to stored

The boundary is clear:

Does it only make sense for one doctype's transition? → CW.sideEffects
Does it work across doctypes or involve multiple documents? → Adapters.d1

authWithPassword is adapter because it spans virtual Login doc + stored User doc. ActivateUser is sideEffect because it only concerns the User document being activated.

Clean separation. No overlap.
