Current code:

javascript

Confirmed: line 654 already treats labels[key] as proof the edge exists and lets execution continue — but line 660 then re-checks dimDef.transitions?.[currentVal], a second, independent source that User.status never populates, so it always rejects regardless of what labels says. This is the actual bug, not a missing field — labels is already correctly read as the edge definition at line 654; transitions is the stale, redundant gate left over from the old shape.

Fix: validate against labels (the edge key itself), not a separate transitions lookup — since key (e.g. "Unverified.Active") is already exactly ${fromVal}.${toVal}, and its presence in labels is the edge:

javascript
  if (dimDef.sideEffects?.[key] === undefined && dimDef.labels?.[key] === undefined) continue

  const currentVal = _getDimValue(doc, dim, dimDef)
  const [fromVal, toVal] = key.split('.')

  // edge exists iff labels (or sideEffects) define this exact key, AND fromVal matches current state
  if (fromVal !== currentVal) {
    _failSignal(`Transition ${key} not allowed from current state ${currentVal} (dim ${dim})`)
    return
  }
  ...

Dropping the validTos.includes(toVal) check entirely — key already encodes both fromVal and toVal together, and its presence in labels/sideEffects (already checked at line 654) is the only proof of existence the new shape provides. No separate transitions map needed, confirmed by reading the refactored User.status — it genuinely has none.
